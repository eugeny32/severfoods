# Центральная админка — admin.severfoods.ru

Отдельное приложение: видит все регионы сразу, строит сводные отчёты, ведёт
реестр регионов и заказчиков. Данные регионов остаются в их собственных базах —
центральная база хранит только реестр, заказчиков, учётные записи и журнал.

## Установка

**1. В панели хостинга создайте:**
- поддомен `admin.severfoods.ru` с корнем в отдельной папке;
- базу данных, например `u3523560_canteen_admin`.

Пользователь MySQL должен иметь доступ **и к этой базе, и ко всем базам
регионов** — на этом держатся сводные отчёты. Если баз касаются разные
пользователи, реквизиты каждого региона указываются в реестре отдельно.

**2. Залейте содержимое папки `admin/`** в корень поддомена.

**3. Создайте `.env`** рядом с `index.php` по образцу `.env.example`.

**4. Откройте `install.php`** — он создаст таблицы и первую учётную запись.
После установки **удалите `install.php` с сервера**.

**5. Проверьте реестр** на странице «Регионы»: в заготовке для Тынды стоит
заполнитель вместо имени базы. Столбец «Доступ» показывает, читается ли база.

## Как проверить, что всё сошлось

Главная проверка — арифметика. Снимите отчёт за один и тот же период в
центральной админке и по отдельности на каждой площадке. Сумма по регионам
обязана совпасть с итогом сводного отчёта. Если не совпала, виновата склейка,
а не данные.

Дальше:
- страница «Обзор» — все регионы читаются, ошибок нет;
- выгрузка в Excel даёт то же число строк, что и на экране;
- вход под учётной записью `viewer` не показывает форм правки;
- восемь неудачных попыток входа подряд блокируют адрес на 15 минут.

## Чем это отличается от региональных площадок

**Вход по паролю, а не по QR-коду.** В регионах вход администратора — это поиск
сотрудника по `qr_code`, пароль не проверяется вовсе. Здесь свой список учётных
записей с хешами паролей, ограничением попыток и журналом. Региональный вход не
менялся.

**Сессия живёт до закрытия браузера** и истекает после 8 часов простоя —
в регионах она держится 30 дней.

**Реестр регионов — таблица, а не код.** В основной системе список захардкожен
в `getRegions()` (`src/regions.php`), и новый регион требует правки PHP и
передеплоя всех площадок. Здесь добавление региона — строка в таблице.

**Сводные отчёты собираются одним запросом через границы баз** (`UNION ALL` по
`имя_базы.таблица`), а не слиянием нескольких выборок в PHP. Группировка и
сортировка остаются на стороне MySQL. Это работает, пока все базы на одном
сервере; для базы на другом сервере в реестре задаются её реквизиты, и такой
регион в сводный запрос не попадёт — его придётся смотреть отдельно.

## Что умеет

- **Обзор** — состояние всех регионов на одной странице.
- **Отчёты** — журнал питания и сухпайки по всем регионам сразу или по
  выбранным, с выгрузкой в Excel.
- **Сотрудники** и **Точки** — списки по всем регионам, добавление и правка с
  явным выбором региона.
- **На связи** — какие точки работают, какие версии стоят, постановка удалённых
  команд.
- **Новый регион** — мастер развёртывания.
- **Регионы**, **Заказчики**, **Журнал**.

## Мастер добавления региона

Порядок: сначала вы создаёте в панели хостинга поддомен и **пустую** базу,
затем мастер делает остальное.

Структура таблиц копируется с региона-образца (`CREATE TABLE … LIKE`), а не
разворачивается из эталонного дампа: канонической схемы в проекте нет — таблицы
в региональных системах создаются лениво, прямо в рантайме, а `database.sql` из
README отсутствует. Копирование даёт точное совпадение и исключает расхождение
схем, из-за которого потом падали бы сводные отчёты.

Мастер **отказывается работать с непустой базой** — иначе одна опечатка в имени
могла бы наложить структуру на действующую площадку.

Вместе со структурой переносится справочник цен ВЖГ: это настройка, а не
накопленные записи, и без него новая площадка считала бы питание по нулю.
Записи о питании, сотрудники и точки не копируются.

В конце мастер создаёт первого супер-администратора и **показывает его QR-код
один раз**. Вход в региональную систему выполняется по этому коду, он же
является паролем — запишите его сразу и храните соответственно.

Создание поддомена и базы остаётся ручным: для автоматизации нужен API панели
хостинга.
